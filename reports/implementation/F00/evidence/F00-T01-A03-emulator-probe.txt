3. CONCLUSIÓN PARA EL ADDENDUM
===============================================================================
- FORMATO DE QUEUE URL (confirmado por documento oficial del mantenedor, por
  documento de terceros y por ejecución real contra el emulador 1.0.491.1):
  https://sqs.us-east-1.amazonaws.com/000000000000/<nombre-de-cola>
  Es la URL canónica que el emulador DEVUELVE y ACEPTA como QueueUrl. El host
  'sqs.us-east-1.amazonaws.com' es un identificador lógico: el tráfico se
  enruta al emulador mediante AWS_ENDPOINT_URL=https://127.0.0.1:9297; en el
  SDK JS v3 hay que fijar useQueueUrlAsEndpoint:false para que no intente
  resolver ese host contra AWS real (fuente: documentación del mantenedor).
  Por tanto NO se escribe ':9297' en SQS_QUEUE_URL/SQS_DLQ_URL: hacerlo sería
  fabricar una QueueUrl que el emulador no devuelve y romper la coherencia con
  el valor que recibirá Terraform/Fase 1. El ':9324' queda eliminado.
- CREDENCIALES: se eliminan AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY fijos y se
  usan AWS_SHARED_CREDENTIALS_FILE=./.local/aws-emulator/emulator_credentials
  y AWS_CONFIG_FILE=./.local/aws-emulator/config, más
  AWS_EC2_METADATA_DISABLED=true (recomendado por la documentación). Se conserva
  AWS_ACCOUNT_ID=000000000000: es el account ID fijo del emulador, no un secreto.
- Matiz de incertidumbre resuelto: la auditoría proponía "apuntar SQS a 9297";
  la evidencia demuestra que el endpoint de transporte es 9297
  (AWS_ENDPOINT_URL) mientras que el identificador de cola conserva el host AWS
  estándar. Se documenta aquí para evitar una futura "corrección" inversa.
